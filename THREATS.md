# TrustVault Threat Model & Matrix (THREATS.md)

## Comprehensive Threat Matrix

| Threat | Attack Scenario | Mitigation in TrustVault | Test Name / Verification | Residual Risk |
|---|---|---|---|---|
| **IDOR** | Attacker accesses doc UUID belonging to another user or tenant. | Centralized `authorize()` chokepoint on every route. Repositories filter by tenant and active grants. | `p10_matrix_idor_mutation.test.ts` -> `IDOR / Cross-Tenant Isolation` | None for guarded routes. |
| **Broken Function-Level Auth** | Viewer calls admin user-creation or owner grant-issue endpoints. | Role guards (`requireRole`) combined with resource-level `authorize()`. | `p10_matrix_idor_mutation.test.ts` -> `Grants management` | None. |
| **Forced Browsing** | Guessing URL paths to access files or admin screens directly. | Server-side auth verification on every API route; UI routing does not bypass server gates. | `p10_matrix_idor_mutation.test.ts` -> `Authorization Matrix` | None. |
| **Search / Count / Autocomplete Leaks** | Attacker queries search or counts to discover document existence or titles. | SQL queries strictly enforce `WHERE (owner_id = $actor OR id IN (SELECT document_id FROM document_grants ...))` before applying search terms or aggregations. | `p4_authorization_chokepoint.test.ts` -> `scoped list query` | None. |
| **Cache / ETag / CDN Leaks** | Browser or intermediary proxies cache decrypted documents. | All sensitive endpoints send `Cache-Control: no-store, no-cache, must-revalidate, private` and `Pragma: no-cache`. | Integration header tests | Decrypted files on client workstation disk if user manually saves them. |
| **Predictable IDs** | Sequential ID guessing (e.g. `/documents/1042`). | All table PKs and external tokens use cryptographically random UUIDv4. | DB migrations schema | None. |
| **Path Traversal** | Filenames like `../../etc/passwd` used to access server disk files. | Physical disk storage names are random UUIDs (`storage_path = uuidv4()`), completely decoupling user filenames from disk paths. | Upload & storage tests | None. |
| **Upload XSS (HTML/SVG)** | Uploading `.html` or `.svg` with embedded scripts executed on download. | Strict extension and magic-byte allowlist. HTML/SVG disallowed. Downloads forced with `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`. Strict CSP blocks inline script execution. | `p10_matrix_idor_mutation.test.ts` -> `Upload validation` | None. |
| **MIME Confusion** | Uploading `.exe` disguised as `.pdf` or spoofing `Content-Type` header. | Server sniffs magic bytes using file header signatures. Extension and magic bytes must strictly match. | `p10_matrix_idor_mutation.test.ts` -> `Upload validation` | None. |
| **Decompression / Zip Bombs** | Uploading nested archives that crash memory or disk during unpacking. | Zip and archive formats are disallowed from the document upload allowlist. Raw size limit enforced upfront (15MB max). | `p10_matrix_idor_mutation.test.ts` -> `rejects oversize files` | None. |
| **CSRF** | Malicious site executes state-changing request with victim's cookies. | Double protection: `SameSite=Strict` cookie plus custom `X-CSRF-Token` header validated on all non-safe HTTP methods. | `p10_matrix_idor_mutation.test.ts` -> `CSRF protection` | Compromise of client script via XSS would yield CSRF token (mitigated by strict CSP). |
| **Session Fixation / Theft** | Attacker steals or pre-sets session ID. | Sessions are opaque 256-bit random tokens stored in DB with SHA-256 hash. Session rotated on login. Flagged `httpOnly`, `Secure`, `SameSite=Strict`. | `p2_auth_sessions.test.ts` | Token compromise if client machine itself is compromised. |
| **Stale Tokens After Revoke** | Revoked user keeps accessing files via long-lived JWT or stale token. | Zero JWTs used. State is stored in DB. Session/grant deletion takes immediate effect on the very next DB check. | `p10_matrix_idor_mutation.test.ts` -> `Revocation` | None. |
| **Share-Link Leakage via Referer** | External link leaked to third-party website via `Referer` header. | `Referrer-Policy: no-referrer` header enforced globally via Helmet. Share links are bound to specific invited email address. | Fastify helmet test | User copy-pasting link into external chat. |
| **Timing / Enumeration on 404 & Login** | Attacker probes doc existence or user email existence via response time or status. | Unknown docs and denied docs return identical status (404) and generic body (`Resource not found or access denied`). Password hash timing mitigated using Argon2id with dummy hash comparison. | `p10_matrix_idor_mutation.test.ts` -> `IDOR / Cross-Tenant Isolation` | Network jitter. |
| **Privilege Escalation via Role Change** | User crafts payload modifying `role` field. | Strict Zod validation schemas discard unexpected fields (`strip()` or `strict()`). User updates disallow modifying one's own role. | Auth schema tests | None. |
| **Mass Assignment** | Attacker submits extra fields like `is_admin: true` during update. | Explicit Zod schemas whitelist allowed fields; repositories explicitly set columns. | Schema validation tests | None. |
| **Race Conditions (Revoke vs Stream)** | Grant revoked while download ticket is generated or in-flight. | Download ticket is single-use, ≤60s expiry. At actual stream time, server re-verifies grant and document state inside transaction before sending bytes. | `p4_authorization_chokepoint.test.ts` | Bytes already buffered over wire before revocation occurred cannot be recalled. |
| **Audit Tampering & Log Injection** | Attacker or rogue admin alters or truncates audit logs. | `audit_events` is append-only. SHA-256 hash chaining records previous event hash. DB triggers abort UPDATE/DELETE/TRUNCATE. Verification endpoint detects break. Newlines/escapes sanitized. | `p6_audit_trail.test.ts` -> `immutability trigger` | DB superuser modifying trigger and hashes (mitigated by separate read-only DB role in prod). |
| **Admin Abuse** | Admin reads confidential documents without explicit permission. | Separation of duties enforced: `admin` role grants user & audit management, NOT document read access. Admins must receive explicit grants to read. | `p10_matrix_idor_mutation.test.ts` -> `admin without grant gets 404` | Admin resetting another user's password to impersonate (audited). |
| **DB Backups Plaintext Leak** | Database backup dumped to disk leaks document files. | Document payloads are encrypted with AES-256-GCM. Per-document random DEK wrapped by environment master key. Ciphertext stored separately from DB metadata. | Crypto test suite | Leakage of both DB dump and environment MASTER_KEY. |
| **Secrets in Repo** | Master key or DB credentials committed to git. | `.env` gitignored, `.env.example` contains only placeholders, pre-commit checks. | Repository review | Developer misconfiguration. |
| **Rate-Limit Bypass** | Attacker brute-forces login from single or rotating IPs. | Global rate limiting (Fastify rate-limit) + per-account consecutive failed login lockout in DB. | `p10_matrix_idor_mutation.test.ts` -> `Login rate limiting` | Distributed botnet targeting multiple unlocked accounts. |
| **Soft-Deleted Docs Reachable** | User queries ID of a soft-deleted document. | `authorize()` checks `deleted_at IS NULL` for non-owners, and only owner can restore. | `p4_authorization_chokepoint.test.ts` -> `soft-delete` | None. |
| **Version History Leak** | Viewer accesses historical version after permission downgrades. | Version fetching routes route through `authorize(actor, docId, 'read')` and verify grant version constraints. | `p4_authorization_chokepoint.test.ts` | None. |
| **CSV Formula Injection** | Attacker names a document `=cmd|' /C calc'!A0` to exploit admin CSV export. | All exported CSV fields are sanitized by prefixing dangerous formula trigger characters (`=`, `+`, `-`, `@`, `\t`, `\r`) with single quotes `'`. | `p7_dashboard_alerts_csv.test.ts` -> `sanitizes formula characters` | None. |
| **AI-Suggestion Widening Access** | AI model hallucinating or tricked into auto-granting permissions. | AI service is strictly suggestive; it has zero grant-writing DB capabilities. Suggestions presented as unselected checkboxes requiring explicit human confirmation. | `p8_ai_suggestions.test.ts` | Human blindly clicking "Confirm" without review. |
| **SSRF** | Server fetching external URLs provided by client. | TrustVault does not accept or fetch remote URLs; uploads are direct multipart file streams. | Codebase inspection | None. |

## Knowingly Accepted Risks (With Justification)

1. **Client-side data persistence after download**: Once encrypted bytes are decrypted and streamed to the user's browser, the server cannot recall or prevent the recipient from saving, screenshotting, or copying the file. *Justification: Fundamental limitation of digital document sharing; mitigated by watermarking recommendations, short-lived download links, and instant future-access revocation.*
2. **Server compromise reading master key**: If the node process runtime memory is compromised, the attacker can access `MASTER_KEY` and decrypt ciphertext. *Justification: Host-level compromise cannot be prevented at the application layer without hardware HSM / KMS integration.*
3. **Database Superuser Audit Tampering**: A PostgreSQL superuser (`postgres`) can drop the immutability trigger and modify rows manually. *Justification: In production, the application connects as an unprivileged role with only `INSERT` and `SELECT` on `audit_events`. DB superuser access is restricted to infrastructure DBAs.*
